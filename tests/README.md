# 数据库入口修复的验证

在项目目录内，使用现有已安装依赖的 Python 解释器运行：

```text
python -B -m unittest discover -s tests -v
```

不要使用全项目测试发现，也不要导入旧批处理脚本；它们可能在顶层执行生产操作。

本测试仅在 tests/ 下创建唯一命名的临时小数据库，结束后清理。图搜测试使用一个内存 FAISS 向量和合成图像，不读取素材、生产索引或模型。

## 已验证

- 缺失数据库时不创建空库，也不回退旧库。
- 文件检查后目标消失，SQLite 的 rw 模式仍不会创建文件。
- 查询连接禁止写入；显式写连接可向临时数据库写入。
- 中文、空格、# 文件名和不同工作目录下的绝对路径连接。
- 字幕关键词返回结构与起止时间保持一致。
- 图搜候选可以从所选数据库找到视频 ID，并完成原有精排流程。

## 手动验证步骤（后续验收时执行）

1. 用现有解释器启动 video_search.py，打开“索引状态”，确认显示主库的 360 个视频、1,591,127 帧和 1,062,422 条字幕（数据新增后以实际只读统计为准）。
2. 选择一个 D 盘视频的特定台词进行文字检索，核对路径和字幕起止时间。
3. 选择一张曾成功检索的截图，核对结果视频和时间点；再用同一截图比较修改前后的排序。数据库连接修复本身不改变模型、预处理或评分。
4. 缺失文件、只读保护等异常场景只运行自动化临时数据库测试，不要重命名、删除或修改生产数据库来验证。

主程序模型和缓存路径现已统一配置。路径专项测试见 test_paths.py；3 个合成短视频的完整隔离流程可显式运行 `python -X utf8 -B tests/run_path_smoke.py`，覆盖现有视频处理脚本、临时索引、匹配与展示缩略图、搜索函数及 Streamlit 页面。全部隔离产物结束后清理，详情见 ../PATHS.md。

生产截图准确率与搜索耗时尚未测量，本轮不做性能优化。
